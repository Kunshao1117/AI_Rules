# Candidate Quality Checklist

Use for a concrete candidate/maintenance review, not as completion governance.

- Admission: beyond ordinary knowledge, correct Policy/Workflow/Agent/Skill/Reference
  owner, existing-owner search complete, reusable specialist method and actual
  demand/value. Two imagined uses or a newly noticed technique are insufficient.
- Trigger fit: narrow description, positive example, near-miss negative example;
  general coding and vague words do not cause loading. Creation is manual_only.
- Method: single responsibility, preserved domain detail, applicable examples,
  no universal language/toolchain assumptions and no duplicated canonical gates.
- Provider: yes/no classification; if specific, required presence, missing behavior,
  no implicit install/login/download or external data transfer.
- Format: name matches eventual directory, ASCII kebab-case up to 64 characters;
  description below 1024 characters, Traditional Chinese meaning first and after
  both Use when: / DO NOT use when: labels; allowed top-level keys only.
- Metadata: author/version/origin and relevant method annotations; no unsupported
  native invocation promises or automatic Memory/persistence requirements.
- References: each has a task-specific read condition; templates/syntax stay there;
  legacy compatibility is excluded from active methods.
- Size: apply the canonical source-document-size policy; move stable details into
  references where needed instead of dropping method knowledge.
- Isolation: candidate outside loader roots; duplicate/owner/trigger checks precede
  concrete approval and separately authorized activation. Never create discovery
  links, registry rows or deployments merely because a draft exists.

If the existing local validator is available, run its format check on the isolated
candidate. Do not install a validator automatically. A format pass is not proof of
method value, trigger quality, authorization, successful activation or completion.
Report unsupported checks honestly; no mandatory notification tool is assumed.
