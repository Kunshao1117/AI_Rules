# Accessibility Observation Checklist

Choose only questions relevant to the selected surface and standard.

| Surface/question | Evidence method |
|---|---|
| Semantic structure | Inspect headings, landmarks, language and reading order in context |
| Form/control identity | Compare visible purpose with accessible name/label, role and state |
| Keyboard path | Actually navigate and activate; observe order, traps and visible focus |
| Dialog/menu transition | Observe appropriate focus entry, containment where applicable, dismissal and return |
| Dynamic status/error | Inspect announced state; use relevant assistive technology where available |
| Image/link meaning | Interpret the contextual alternative/name; decorative images differ from meaningful images |
| Contrast/reflow | Measure and observe under the applicable criterion and content assumptions |

Retain scanner target/rule/help information, but a scanner's severity is not an
independent project risk verdict. Missing labels, unclear links or heading issues
need contextual interpretation. Do not apply a blanket numeric threshold to all
text/control sizes. A rendered screenshot does not prove keyboard operation.
An agent may collect available keyboard/focus evidence; unsupported screen-reader
interaction remains a limitation, not fabricated evidence or a forced user task.

Official guidance checked 2026-09-15:
- [W3C evaluation tool limits](https://www.w3.org/WAI/test-evaluate/tools/selecting/): automated tools assist evaluation and cannot settle every accessibility question.
- [W3C WCAG overview](https://www.w3.org/WAI/standards-guidelines/wcag/): use the version/level relevant to the project's requirements; this reference does not choose a universal target or offer a legal determination.
